    OHand Communication Protocol V3.0

    1. Communication Protocol Overview

    The host control unit sends command data to obtain the status of, and control, the dexterous hand. The host system sends read commands to the ROH dexterous hand. After receiving the command data and verifying it successfully, the ROH dexterous hand returns the corresponding result to the host system.

    Note: The CAN protocol and the serial port protocol share the same command format. The CAN protocol uses CAN messages, with 8 bytes per frame, and the CAN ID matches the dexterous hand ID.

    2. Communication Parameters

    Both RS232 and RS485 use the following communication parameters: 115200bps, 8 data bits, 1 stop bit, no parity.

    The CAN communication parameter is 1000000bps.

    3. Dexterous Hand Serial Command Frame Format

    The command frame format for operating the ROH dexterous hand is as follows:

    Byte Value Description
    byte[0] 0x55 Packet header
    byte[1] 0xAA Packet header
    byte[2] HandID ROH dexterous hand ID
    byte[3] MasterID Master ID
    byte[4] Command Operation command
    byte[5] DataLen Length of the data portion of this frame, i.e. byte[6]..byte[6 + DataLen - 1]
    byte[6]..byte[6 + DataLen - 1] Data[0]..Data[DataLen-1] Command data
    byte[6 + DataLen] Checksum Checksum (see 4. LRC Checksum Calculation)

    The ROH dexterous hand response frame to a command is as follows:

    Byte Value Description
    byte[0] 0x55 Packet header
    byte[1] 0xAA Packet header
    byte[2] MasterID Master ID
    byte[3] HandID ROH dexterous hand ID
    byte[4] Command Operation command. If the command execution fails, the most significant bit is 1 and the lower seven bits are the operation command; Data[0] is the error code (see 6. Dexterous Hand Error Codes)
    byte[5] DataLen Length of the data portion of this frame, i.e. byte[6]..byte[6 + DataLen - 1]
    byte[6]..byte[6 + DataLen - 1] Data[0]..Data[DataLen - 1] Return data
    byte[6 + DataLen] Checksum Checksum (see 4. LRC Checksum Calculation)

    Example:

    Command frame (HEX):

    Header Dexterous Hand ID Master ID Operation Command Data Length Data Checksum
    55 AA 02 01 50 12 10 27 FF 10 27 FF 10 27 FF 10 27 FF 10 27 FF 10 27 FF 66

    Success response frame (HEX):

    Header Master ID Dexterous Hand ID Operation Command Data Length Data Checksum
    55 AA 01 02 50 00 NULL 53

    Error response frame (HEX):

    Header Master ID Dexterous Hand ID Operation Command Data Length Data Checksum
    55 AA 01 02 D0 01 01 D3

    Note: The operation command is the value of the command frame's opcode OR'd with 0x80, and the data byte is the error code.

    4. LRC Checksum Calculation

    The XOR of bytes byte[2]..byte[6 + DataLen - 1] in the dexterous hand serial command frame:

    uint8_t buf[...];
uint8_t lrc = 0;
uint8_t cmd_data_len = 4/* sizeof(MasterID) + sizeof(HandID) + sizeof(Command) + sizeof(DataLen) */ + DataLen;

/* Fill buf */
buf[0] = 0x55;
buf[1] = 0xAA;
...

for (int i=0; i<cmd_data_len; i++)
    lrc ^= buf[2 + i];

buf[2 + cmd_data_len] = lrc;

    1. Unless otherwise specified, single-byte data is of type uint8; XXX_L, XXX_H denote the low and high bytes of a uint16; XXX_BYTE0, XXX_BYTE1, XXX_BYTE2, XXX_BYTE3 denote the four bytes of a uint32 from low to high;
    2. If specified as float32, XXX_BYTE0, XXX_BYTE1, XXX_BYTE2, XXX_BYTE3 denote the four bytes of a float32 from low to high.

    6. Dexterous Hand Error Codes

    Error Name Code Description Group
    ERR_PROTOCOL_WRONG_CRC 0x01 Checksum error Protocol
    ERR_COMMAND_INVALID 0x11 Invalid command Command
    ERR_COMMAND_INVALID_BYTE_COUNT 0x12 Incorrect byte count Command
    ERR_COMMAND_INVALID_DATA 0x13 Invalid value Command
    ERR_STATUS_INIT 0x21 Waiting for initialization command or initializing Status
    ERR_STATUS_CALI 0x22 Waiting for calibration Status
    ERR_STATUS_STUCK 0x23 Motor stalled Status
    ERR_OP_FAILED 0x31 Operation failed Operation
    ERR_SAVE_FAILED 0x32 Save failed Operation
